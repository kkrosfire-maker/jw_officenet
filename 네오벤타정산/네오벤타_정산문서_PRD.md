# PRD: 네오벤타 정산문서 (v1.1)

- 작성일: 2026-09-28 / 개정: 2026-09-29
- 사용자: Kevin 1인
- 환경: Windows PC 로컬 (Python 설치 가능)
- 상태: MVP 범위 확정. 추가 기능은 이후 버전에 반영

### v1.1 변경 요약
- **요율표(정원유니어스 요율표)를 약가·수수료·구분·제약사·비고의 기준**으로 삼는다. 변환엑셀의 VLOOKUP 방식을 대체한다.
- 제품은 **보험코드**로 식별한다. 최종 제품명은 앱이 관리하는 "제품 마스터"로 기존 이름을 유지한다.
- 새 요율표를 넣으면 이전 버전과 비교해 **변경 알림**을 띄우고, 앱 안에서 승인하거나 수정한다.
- lawdata 단가와 요율표 약가가 다르면 **어느 값을 쓸지 반드시 사용자에게 묻는다.**
- 요율표 비고의 정산 제한 조건(신규금지, 정산가능 기간)을 검사한다.

## 1. 개요

### 1.1 목적
매월 받는 **lawdata**(EDI 처방 원본 엑셀)를 넣으면 **요율표**와 **제품 마스터**로 자동 변환해서 **최종 정산 엑셀**(`2026년 거래처별 세부내역` 시트의 DB 표)에 새 행을 추가하는 로컬 앱을 만든다.

### 1.2 해결할 문제
- 매달 붙여넣기, VLOOKUP 변환, 소액처 판정, 종합 시트 입력을 손으로 반복하고 있다.
- 기준정보가 바뀌어도(약가 변동, 수수료 변동, 제품명 변경, 판매 제한) 알아챌 방법이 없다.
- 기존 데이터에서 확인한 실제 오류 사례:
  - 변환자료 단가 오류: 카프릴정 170원 (실제 497원), 토피솔밀크로션 3,754원 (실제 3,574원)
  - 수수료 변동을 반영하지 못함: 코부테롤패취는 26.03 EDI부터 36%→40%인데 7월 정산에 36%로 적용됨
  - lawdata 단가 오류: 오바램정 1,500원 (실제 2,500원)
  - 처방월 오기: 9월 정산 이의원 푸라칸

### 1.3 목표
- 파일을 넣고 정산월을 선택한 뒤 버튼 한 번으로 최종 엑셀을 만든다.
- **값이 다르거나, 변경되었거나, 제한에 걸리는 행만 사람이 확인한다.**
- 한 달 처리 시간 5분 이내.

## 2. 입력 데이터

| 구분 | 파일 예시 | 사용하는 부분 | 사용 빈도 |
|---|---|---|---|
| lawdata | `lawdata.xlsx` | 월별 시트(`6월`, `7월`, …), 1행이 헤더 | 매월 |
| **요율표** | `정원유니어스 요율표 26.08.xlsx` | `제품별 수수료` 시트(2행이 헤더, 약 11,000행), `제약사별 프로모션` 시트 | **업데이트가 있을 때만** 사용자가 추가 |
| 최종 엑셀 | `최종엑셀.xlsx` | `2026년 거래처별 세부내역` 시트의 **DB 표**(헤더 7행, A7:S…), `종합` 시트, `제약사별 매출현황` 피벗 | 매월 |
| 변환 엑셀 | `변환엑셀.xlsx` | `변환자료`, `금액인정` 시트 | **처음 한 번**만 (제품 마스터와 인정금액 초기화용) |

> 샘플 파일은 `samples/` 폴더에 넣어두고 개발과 테스트에 쓴다. 대상은 lawdata 6~9월, 변환엑셀, 최종엑셀, 요율표 26.08이다.

### 2.1 lawdata 주의사항
- **컬럼 위치가 월마다 다르다.** 예를 들어 6월 시트에는 `지급유형`이 없다. 반드시 **헤더 이름으로** 컬럼을 찾는다.
- 한 시트 안에 과거 정산월 데이터가 쌓여 있을 수 있다(예: `7월` 시트는 2~7월 정산분 221행). **`정산월` 값으로 필터링**한다.
- 이름이 중복된 컬럼(`수정자`)과 헤더가 없는 컬럼(7월 AO열)은 **무시**한다.
- 사용하는 헤더: `처방월`, `정산월`, `거래처`, `사업자등록번호`, `보험코드`, `제품`, `제조사`, `단가`, `수량(원외)`

### 2.2 요율표 주의사항
- `제품별 수수료` 시트의 컬럼: `보험코드`(E), `구분`(F), `제약사명`(G), `제품명`(H), `약가`(I), `요율`(J), `비고`(K)
- 보험코드는 **문자열**로 읽는다(앞자리 0 유지, `SB…`나 `SC…` 코드 있음).
- 요율표 안에 **같은 보험코드가 여러 행**인 경우가 있다(현재 69개. 우리 제품은 해당 없음). 우리 제품이 이런 경우에 걸리면 어느 행을 쓸지 사용자에게 묻는다.
- 요율표의 `제품명`은 최종파일 제품명과 표기가 다르다(성분 괄호, 띄어쓰기, 관례명). **최종 제품명으로 쓰지 않는다.**

## 3. 데이터 모델 (앱이 관리)

앱은 `data/` 폴더에 기준정보를 보관한다. 사람이 엑셀로도 열어볼 수 있는 형식이어야 한다.

### 3.1 요율표 버전 (`data/rate_tables/`)
- 사용자가 추가한 요율표 원본을 `요율표_YYYY-MM-DD.xlsx`로 복사해 보관한다. 가장 최근에 승인한 버전이 **현재 요율표**가 된다.
- 요율표에서 쓰는 값: **약가, 요율(=제약사 수수료%), 구분, 제약사명, 비고**

### 3.2 제품 마스터 (`data/product_master.xlsx`)
보험코드 한 개당 한 행이다. 요율표에 없는, 우리만의 값을 보관한다.

| 필드 | 설명 |
|---|---|
| 보험코드 | 키 |
| 최종 제품명 | 최종 DB H열에 들어갈 이름 (예: `디부루펜정`) |
| lawdata 약제명 별칭 | lawdata에서 이 제품으로 인정할 이름 목록 (예: `코미정`, `코미정[삭제된 제품]`) |
| 이전 보험코드 | 코드가 바뀐 경우 옛 코드 목록 (예: 코미정 `SC6228163` → `SB0361186`) |
| 구간인센% | 요율표에 없음. 앱에서 관리 |
| 특별인센% | 요율표에 없음. 앱에서 관리 |
| 제외 여부 / 메모 | 정산에서 제외할 제품(예: 정산불가)과 메모 |

**초기화(첫 실행 때 한 번):**
1. lawdata 전체 시트에서 `제품 ↔ 보험코드` 쌍을 모은다(6~9월 기준 49쌍, 1:1 대응).
2. 변환자료 `약제명`으로 연결해 `변경명` → 최종 제품명, 구간인센%, 특별인센%를 가져온다.
3. 보험코드를 찾지 못한 변환자료 행(lawdata에 한 번도 나오지 않은 제품 34개)은 "코드 미확인" 상태로 넣어둔다. 해당 제품이 lawdata에 처음 나올 때 연결한다.
4. **초기화 대조 리포트**를 만든다: 변환자료 값과 요율표 값이 다른 항목. 현재 알려진 차이는 카프릴정 단가, 토피솔 단가, 코부테롤 수수료다. 이후 계산에는 **요율표 값을 쓰고**, 리포트는 사용자에게 보여준다.

### 3.3 제약사 설정 (`data/settings.json`)
- **제약사명 별칭:** 요율표 이름 → 최종파일 표기. 예: `유니메드제약` → `유니메드`. 앱에서 편집할 수 있다.
- **최소 인정금액:** 금액인정 시트로 초기화한다. "10만원" → 100000, "없음" → 판정 안 함. 형식이 애매한 값(`10만원 (26.04부터)`, `1만원 이상` 등)은 사용자가 숫자로 입력한다. **안국뉴팜은 100000.**

### 3.4 변경 이력 (`data/change_log.csv`)
앱에서 일어난 모든 변경을 기록한다: 요율표 승인, 마스터 편집, 검토 중 선택.
기록 항목: 일시, 대상(보험코드, 제품명), 항목, 이전 값, 새 값, 사유(자유 입력), 적용 EDI월(처방월 기준)

## 4. 변환 규칙

### 4.1 추출
1. 사용자가 lawdata 시트와 정산월(YYYY-MM)을 선택한다. 시트는 정산월로 자동 추천한다.
2. `정산월` = 선택한 월인 행만 가져온다.
3. **원본 행 순서를 그대로 유지한다.**

### 4.2 제품 매칭 (3단계)
1. **보험코드**가 제품 마스터(또는 이전 보험코드)에 있으면 → 매칭 완료
2. 없으면 lawdata **약제명**이 마스터의 별칭 목록에 있는지 확인 → 있으면 `PRODUCT_CODE_CHANGED`(보험코드 변경 확인)
3. 없으면 **비슷한 이름**을 찾는다. 이름 정규화: `[삭제된 제품]`, `(…)`, `_(…)`, 공백 제거. 비슷한 후보가 있으면 `PRODUCT_RENAMED`(추천 제품으로 연결할지 확인)
4. 그래도 없으면 `NEW_PRODUCT`

연결을 확인하면 새 약제명과 보험코드를 마스터의 별칭과 이전 코드에 추가한다. 다음 달부터는 자동으로 매칭된다.

### 4.3 컬럼 매핑 (최종 DB 표)

| 열 | 헤더 | 값 | 출처 |
|---|---|---|---|
| A | 수탁업체명 | `네오벤타㈜` (고정) | – |
| B | 처방월 | lawdata `처방월` → 해당 월 1일 날짜. **lawdata 값 그대로** | lawdata |
| C | 정산월 | lawdata `정산월` → 해당 월 1일 날짜 | lawdata |
| D | 사업자번호 | `사업자등록번호` | lawdata |
| E | 병원명 | `거래처` | lawdata |
| F | 제약사 | 요율표 `제약사명` → 별칭 적용 (예: `유니메드제약` → `유니메드`) | 요율표 |
| G | 제약사 구분 | 요율표 `구분`을 **그대로** (예: 3, 2, `유니`) | 요율표 |
| H | 제품명 | 제품 마스터 `최종 제품명` | 마스터 |
| I | 단가 | 요율표 `약가`. **lawdata 단가와 다르면 사용자가 선택**(4.5) | 요율표/사용자 |
| J | 수량 | `수량(원외)` | lawdata |
| K | 금액 | 수식 `=DB[[#This Row],[수량]]*DB[[#This Row],[단가]]` | – |
| L | 제약사 수수료% | 요율표 `요율` | 요율표 |
| M | 제약사 구간인센% | 마스터 `구간인센%` | 마스터 |
| N | 제약사 특별인센% | 마스터 `특별인센%` | 마스터 |
| O | 최종요율 | 수식 `=N{r}+M{r}+L{r}-1%` (정산수수료 1% 차감) | – |
| P | 확정금액 | 일반: 수식 `=DB[[#This Row],[금액]]*O{r}` / 소액처: `0` | – |
| Q | 비고 | 비워둠 | – |
| R | 정책1 | 비워둠 | – |
| S | 정산내역확인 | 소액처면 `소액처`, 아니면 비워둠 | – |

> 구분(G)과 제약사(F)는 이제 요율표를 따른다. 그래서 과거 최종파일 값과 다를 수 있다. 예: 안국뉴팜 구분이 과거 `1`에서 `3`으로, 유니메드 구분이 과거 `유`에서 `유니`로 바뀐다. 의도된 변경이다.

### 4.4 소액처 판정
- 같은 정산월 안에서 **(병원명 × 제약사)** 그룹의 금액 합계(확정 단가 × 수량)를 구한다.
- 합계가 해당 제약사의 최소 인정금액보다 **작으면** 그룹 전체 행을 소액처로 처리한다: P = `0`, S = `소액처`
- 최소 인정금액이 "없음"인 제약사(예: 보령제약)는 판정하지 않는다.
- 판정은 **검토를 모두 끝낸 뒤**(단가 선택, 제외 행 반영) 다시 계산한다.
- 과거 데이터에서 S열이 `0`인 행은 옛 표기(확정금액 0 = 미지급)다. 앱은 `소액처` 표기만 쓴다.

### 4.5 검토 항목 (확인 필요)
아래 경우는 자동으로 확정하지 않는다. **검토 화면**에서 모두 처리해야 "생성" 버튼이 켜진다.

| 코드 | 조건 | 사용자 조치 |
|---|---|---|
| `PRICE_MISMATCH` | lawdata 단가 ≠ 요율표 약가 (예: 오바램정 1,500 vs 2,500) | **둘 중 하나를 반드시 선택**하거나 직접 입력. 기본값을 미리 정하지 않는다 |
| `PRODUCT_CODE_CHANGED` | 약제명은 알지만 보험코드가 새 코드 | 같은 제품인지 확인하면 마스터에 코드 추가 |
| `PRODUCT_RENAMED` | 코드와 이름 모두 모르지만 비슷한 기존 제품이 있음 | 추천 제품으로 연결하거나 신규로 등록 |
| `NEW_PRODUCT` | 매칭 실패 | 요율표에 보험코드가 있으면 요율표 값을 자동으로 채우고, 최종 제품명은 규칙으로 추천(성분 괄호와 공백 제거, 예: `오바램정 100mg (실데나필)` → `오바램정100mg`). 사용자는 제품명, 구간인센, 특별인센을 확인하거나 입력한 뒤 마스터에 저장 |
| `NOT_IN_RATE_TABLE` | 현재 요율표에 보험코드가 없음 | 약가, 수수료, 구분, 제약사를 직접 입력하거나 제외 |
| `RATE_TABLE_DUP` | 요율표에 같은 보험코드가 여러 행 | 사용할 행 선택 |
| `NOTE_RESTRICTION` | 요율표 비고의 제한 조건에 해당함(4.6) | 포함하거나 제외 |
| `EXCLUDED_PRODUCT` | 마스터에서 제외로 표시한 제품(예: 정산불가) | 포함하거나 제외 |
| `VALUE_CHANGED` | 이번 달 적용값(약가, 수수료, 구간인센, 특별인센)이 최종 DB에서 같은 제품에 **마지막으로 적용한 값**과 다름 | 의도한 변경인지 확인(이전 값과 새 값을 나란히 표시) |
| `NO_THRESHOLD` | 제약사 최소 인정금액을 모름 | 금액 입력(설정에 저장) |
| `DUPLICATE_MONTH` | 최종 DB에 이미 같은 정산월 행이 있음 | 중단하거나 기존 행을 교체 |

- 검토에서 선택한 내용은 모두 `change_log.csv`에 기록한다.
- 같은 종류의 항목은 **한꺼번에 처리**할 수 있게 한다. 예: "이 제품 전체에 요율표 약가 적용".

### 4.6 요율표 비고 제한 조건
비고를 아래 패턴으로 해석한다. **"○월 EDI"는 처방월을 뜻한다. 따라서 lawdata `처방월`과 비교한다.** (정산월이 아님)

| 패턴 예 | 해석 | 검토 조건 |
|---|---|---|
| `26년 3월 EDI까지 정산가능` | 종료 처방월 = 2026-03 | 처방월 > 종료월 |
| `25년 11월 EDI부터 정산가능`, `26년 1월 EDI부터 정산재개` | 시작 처방월 | 처방월 < 시작월 |
| `신규금지 (26.07 EDI부터)` | 시작 처방월 이후 신규 거래처 금지 | 처방월 ≥ 시작월 **이고** 해당 병원이 이 제품의 **신규처**인 경우. 신규처 = 최종 DB에 처방월이 시작월보다 앞선, 같은 병원 × 같은 제품 행이 없음 |

예: 코미정 한 행이 처방월 2026-03, 정산월 2026-04이면 "26년 3월 EDI까지"에 **해당하므로 정산 가능**하다.

같은 원칙을 요율표 비고의 약가·수수료 변동 문구에도 적용한다(예: `26년 3월 EDI부터 수수료 변동(36%→40%)` = 처방월 2026-03부터 적용).

- 해석하지 못한 비고(예: `25.12 일부 제조번호 회수조치`, `[집중 프로모션 44%→63%]`)는 막지 않고 **참고 정보**로 해당 행 옆에 표시한다.
- `제약사별 프로모션` 시트에 해당 보험코드가 있으면 프로모션 문구를 참고로 표시한다. 특별인센에 자동으로 반영하지는 않는다.

## 5. 요율표 업데이트 (변경 감지)

요율표는 매달이 아니라 **업데이트가 있을 때만** 사용자가 추가한다.

1. 사용자가 새 요율표 파일을 추가한다.
2. 앱이 현재 요율표와 **보험코드 기준으로 비교**한다. 비교 대상은 **우리 제품 마스터에 있는 코드만**이다(요율표 전체 11,000행이 아님).
3. **변경 알림 화면**에 아래 항목을 표로 보여준다.
   - 약가 변경 (이전 → 새 값)
   - 요율(수수료) 변경
   - 구분 변경, 제약사명 변경
   - 비고 추가, 변경, 삭제
   - 우리 제품 코드가 새 요율표에서 사라짐
4. 사용자는 항목별로 승인하거나 이전 값을 유지하고, 사유를 적을 수 있다. 승인이 끝나면 새 요율표가 현재 버전이 된다.
5. 변경 내용은 `change_log.csv`에 남긴다.
6. 앱 상단에 알림 배지로 "승인 대기 중인 요율표 변경 N건"을 표시한다.

## 6. 기준정보 편집 (앱 안에서)

**기준정보 관리 화면**에서 아래 항목을 편집한다.
- **제품 마스터:** 최종 제품명, 별칭, 이전 코드, 구간인센%, 특별인센%, 제외 여부, 메모. 검색과 정렬을 지원한다.
- **제약사 설정:** 이름 별칭, 최소 인정금액
- **요율표 값 덮어쓰기(예외):** 특정 보험코드의 약가나 수수료를 요율표와 다르게 써야 할 때 쓴다. 덮어쓴 값은 **적용 시작 EDI월(처방월 기준)**과 사유를 필수로 입력한다. 덮어쓴 값은 처방월이 시작월 이상인 행에만 적용한다. 덮어쓴 항목은 목록에 항상 표시된다.

저장할 때마다 `data/backup/`에 이전 파일을 자동 백업하고, 변경 이력을 기록한다.

## 7. 최종 엑셀 출력

1. **원본 파일은 수정하지 않는다.** `최종엑셀_YYYY-MM_생성.xlsx`로 새 파일을 저장한다.
2. DB 표의 마지막 행 다음에 행을 추가하고, **표 범위(`DB` ref)를 늘린다.** 기존 행의 서식(날짜, 숫자, 퍼센트, 테두리)을 복사한다.
3. `종합` 시트 **B18(계산서 발행액)** = 이번 정산월 확정금액 합계를 **숫자 값**으로 넣는다. B20(전월 누락분)은 손대지 않는다.
4. `제약사별 매출현황` 피벗은 **파일을 열 때 자동 새로고침**되도록 설정한다(`refreshOnLoad=True`).
5. 저장 후 결과 요약을 보여준다: 추가 행 수, 금액 합계, 확정금액 합계, 소액처 그룹과 행 수, 검토 처리 내역.

> openpyxl은 수식을 계산하지 않는다. 확정금액 합계는 **파이썬에서 직접 계산**한다(금액 × 최종요율, 소액처는 0).

## 9. 기술 구성

- Python 3.11+, `streamlit`, `openpyxl`, `pandas`, 이름 유사도 비교는 표준 라이브러리 `difflib`
- 실행: `run.bat`을 더블클릭하면 가상환경을 활성화하고 `streamlit run app.py`를 실행해 브라우저가 열린다.
- 구조
  ```
  neoventa-settlement/
    app.py                      # Streamlit 진입점
    pages/                      # 정산 실행, 요율표 업데이트, 기준정보 관리, 변경 이력
    core/
      lawdata.py                # 헤더 기반 로딩, 정산월 필터
      rate_table.py             # 요율표 로딩, 버전 관리, 버전 간 비교
      master.py                 # 제품 마스터, 설정, 초기화, 백업, 변경 이력
      matcher.py                # 3단계 제품 매칭, 제품명 추천 규칙
      notes.py                  # 비고 제한 조건 해석
      converter.py              # 매핑, 검토 항목 생성, 소액처 판정
      writer.py                 # DB 표 행 추가, 종합 B18 입력, 피벗 새로고침
    data/                       # rate_tables/, product_master.xlsx, settings.json, change_log.csv, backup/
    samples/
    tests/
    run.bat, requirements.txt, README.md
  ```
- 로직(`core/`)과 UI를 분리해서 `pytest`로 테스트할 수 있게 한다.

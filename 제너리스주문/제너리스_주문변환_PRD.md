## 1. 배경 및 문제 정의

Kevin은 제너리스라는 병원에 진료소모품·약품을 납품하고 있다. 병원은 자체적으로 편한 명칭(구두 표현, 손글씨, 사진)으로 주문 목록을 보내오는데, 이 명칭은 실제 제조사가 사용하는 표준 품목명과 일치하지 않는 경우가 많다. Kevin은 이 주문을 처리하기 위해 매번 다음 과정을 수작업으로 반복하고 있다.

1. 병원이 보낸 사진/텍스트 주문 목록을 읽고 해석한다.
2. 각 항목이 어떤 표준 제품(제조사, 제품명, 규격)에 해당하는지 자신의 기억과 과거 엑셀 자료를 뒤져 매칭한다.
3. 의약품 특성상 자주 바뀌는 매입가/매출가를 최신 값으로 확인하거나 새로 정한다.
4. 매칭·가격 확정이 끝나면 발주처에 보낼 양식에 맞춰 엑셀을 새로 작성한다.
5. 목록에 없는 새 품목이면 어떤 제품인지 직접 찾아봐야 한다.

이 과정은 반복적이고 실수가 발생하기 쉬우며(실제로 보유 자료에도 "실매출가 792원 → 79,500원", "매입가가 매출가보다 높음(역마진)" 같은 과거 오류 수정 이력이 다수 존재), 병원 표현과 표준 품목명이 1:1로 고정되어 있지 않아 사람이 계속 개입해야 한다.

## 2. 목표

- 병원이 보낸 사진 한 장으로 주문 항목을 인식하고, 표준 품목(제조사/제품명/규격/현재가)과 자동으로 매칭한다.
- 매칭·가격 수정을 실시간으로 반영하고, 발주처 제출용 엑셀 양식으로 즉시 내보낸다.
- 사람이 고친 매칭/가격 정보를 프로그램이 "학습"하여 다음 주문부터는 더 정확해지게 한다.
- 처음 보는 품목은 인터넷에서 정보를 찾아 등록을 돕고, 유사 대안 제품을 제시한다.
- 궁극적으로 "사진 첨부 → 검수 → 엑셀 발송"까지의 시간을 최소화하고, 가격/매칭 오류로 인한 손실을 줄인다.

### 성공 지표 (제안)

| 지표 | 현재(수작업 추정) | 목표 |
|---|---|---|
| 주문 1건(품목 10~15개) 처리 시간 | 15~30분 | 5분 이내 |
| 자동 매칭 성공률(사람 확인 없이 맞는 비율) | - | 3개월 사용 후 80% 이상 |
| 가격 오류(역마진, 이상치) 발생 건수 | 과거 이력상 다수 발견 | 0건에 근접 |
| 미등록 품목 조사 시간 | 수동 검색 | 자동 정보 수집으로 단축 |

## 4. 현재 보유 자료 분석 (참고 데이터)

제공해주신 두 파일을 분석한 결과, 이미 아래와 같은 구조의 자료가 확보되어 있다. 이 구조를 프로그램의 데이터 모델 기반으로 삼는다.

### 4.1 마스터 품목 단가표 — `01.제너리스_주문 최종.xlsx` (시트: 품목별 단가)

병원 주문명 ↔ 표준 제품 정보 ↔ 현재 매입/매출가를 연결하는 핵심 마스터 데이터. 119개 품목, 아래 컬럼 보유:

| 컬럼 | 설명 |
|---|---|
| 항목 | 대분류 (니들/시린지/캐뉼라·카테터/수액/앰플/약품/장갑/소독위생/드레싱 등) |
| 제너리스주문명 | 병원이 실제로 쓰는 호칭(별칭) — **인식된 텍스트가 매칭을 시도할 대상** |
| 제조사 | 제조/유통사명 |
| 제품명 | 제조사 표준 품목명 (규격/거래처 코드가 함께 적힌 원문) |
| 규격 | 사이즈/용량 등 규격 |
| 기준일자 | 해당 가격의 최근 확인/명세일자 |
| 실매입가 / 실매출가 | 현재 단가 |
| 이익금액 / 이익률(%) / 마진율(%) | 자동 계산 가능한 파생값 |
| 급여구분 / 분류근거 | 건강보험 급여·비급여 구분(참고용, 추정치) |
| 비고 | 가격 변경 이력, 이상치 경고 등 자유 메모 |

**참고할 점**: 같은 "제너리스주문명"이라도 여러 제조사/규격의 제품이 매칭될 수 있음(예: "23G needle"이 정림/성심메디칼 두 제조사로 각각 존재). 즉 병원 명칭 하나가 여러 후보 표준품목에 대응할 수 있는 **N:1이 아닌 N:M 매칭 구조**임을 데이터 모델에 반영해야 한다.

### 4.2 발주처 제출용 양식 — `260907 제너리스 주문.xlsx`

실제로 완성해서 보낸 주문서 예시. 목표 산출물의 형태:

| 품목(병원 원문) | 수량 | 요청사항(병원 원문 상세) | 품목(표준 규격) | 매입가 | 매출가 |
|---|---|---|---|---|---|
| 3way | 2 | 3way(협성)/0/온더스/제너리스 | 0 | 12,300 | 13,200 |
| 1cc 시린지 | 4 | 일회용주사기/성심 | 1cc/26G | 5,300 | 6,500 |
| 마운자로 2.5 | 3 | (냉장)마운자로프리필드펜주2.5mg/0.5ml | 4펜 | 265,553 | 272,505 |

이 파일이 곧 **1번 기능(사진 인식→매칭→엑셀 생성)의 최종 출력 포맷**이 된다.

## 5. 기능 요구사항

### FR-1. 사진 인식 → 자동 매칭 → 엑셀 생성

- **입력**: 병원이 보낸 주문 사진(손글씨 또는 프린트, 1장 이상) 업로드.
- **OCR/인식**: 이미지에서 텍스트를 추출한다. 한글 손글씨는 인식률이 낮을 수 있으므로, 인식 결과를 사람이 바로 확인/수정할 수 있는 화면이 반드시 필요하다(전자동을 전제하지 않음).
- **파싱**: 추출된 텍스트에서 "품목명 + 수량"을 분리한다(예: "3way 2개" → 품목="3way", 수량=2).
- **매칭**: 파싱된 품목명을 마스터 DB의 "제너리스주문명"(및 과거에 학습된 별칭들)과 유사도 매칭한다.
  - 완전/높은 유사도 일치 → 자동 확정(단, 후보가 2개 이상이면 선택 UI 노출).
  - 낮은 유사도/불일치 → 후보 리스트(상위 3~5개)를 보여주고 사용자가 선택, 혹은 "신규 품목"으로 분류(FR-4로 연결).
- **가격 채움**: 매칭된 표준 품목의 최신 매입가/매출가를 자동으로 채운다. 단, 마스터 DB의 기준일자가 오래된 경우 "가격 확인 필요" 경고를 표시한다(의약품 가격 변동 특성 반영).
- **출력**: 4.2에서 정의한 양식(품목/수량/요청사항/품목/매입가/매출가)으로 엑셀 생성 및 저장/내보내기.

### FR-2. 실시간 수정 반영

- 매칭 결과 화면(엑셀형 편집 그리드)에서 품목 재매칭, 수량, 매입가, 매출가를 직접 수정 가능.
- 수정 시 이익금액/이익률/마진율 등 파생값이 즉시 재계산되어 화면에 표시.
- 마스터 DB 대비 가격이 비정상적으로 튀는 경우(예: 과거 자료의 "792원 → 79,500원" 같은 100배 격차, 역마진 등) 저장 전에 경고 표시.

### FR-3. 수정 내용 저장(학습)

- 사용자가 확정한 매칭/가격 수정 내용은 마스터 DB에 반영되어 **다음 주문부터 자동 반영**된다.
  - 새로운 병원 표현이 특정 표준 품목에 매칭되면, 그 표현을 해당 품목의 별칭으로 저장(향후 자동 매칭 정확도 향상).
  - 가격이 변경되면 마스터 DB의 실매입가/실매출가와 기준일자를 갱신하고, 변경 이력을 비고란 형태로 로그에 남긴다(기존 자료의 "OO원 → OO원으로 수정" 방식 계승).
- 되돌리기(undo)/이력 조회가 가능해야 한다 — 잘못 저장한 경우 이전 값으로 복구 가능.
- 저장 위치는 로컬(사용자 PC)을 기본으로 하며, 주기적 백업(예: 날짜별 엑셀/DB 스냅샷)을 권장.

### FR-4. 미등록 품목 인터넷 검색

- 매칭 실패(마스터 DB에 없는 품목)로 분류된 항목에 대해, 인식된 텍스트(및 사진에 함께 찍힌 정보)를 바탕으로 인터넷 검색을 수행하여 아래 정보를 수집한다.
  - 제조사, 정확한 표준 제품명, 규격, 참고 가격대, 구매 가능 거래처/링크.
- 검색 결과는 사용자가 검토 후 "마스터 DB에 신규 품목으로 등록" 또는 "폐기"를 선택할 수 있는 화면으로 제시.
- 신규 등록 시 FR-1의 매칭 대상에 즉시 포함되어야 한다.

### FR-5. 대안 제품 제안

- FR-4의 검색 결과 및/또는 마스터 DB 내 같은 "항목(대분류)"·유사 "규격"을 가진 기존 품목을 근거로, 대체 가능한 제품을 제안한다.
  - 활용 시나리오: 특정 제조사 품절/단가 급등 시 대안 제조사 제품 확인, 신규 품목 등록 시 비슷한 기존 품목과 가격 비교.
- 제안 시 비교 근거(가격, 제조사, 규격 유사도)를 함께 표시하여 사용자가 판단할 수 있게 한다.

**가격 변경 이력 테이블**
`이력ID, 품목ID, 변경일자, 이전매입가, 이후매입가, 이전매출가, 이후매출가, 변경사유/메모`

## 7. 비기능 요구사항

- **플랫폼**: Windows PC 데스크톱에서 실행 가능한 프로그램(설치형 또는 실행 파일 형태). 인터넷 연결 필요(OCR/검색 기능용). 오프라인에서도 기존 마스터 DB 기반 수동 매칭·엑셀 편집은 가능해야 한다.
- **데이터 보관**: 로컬 저장 기본, 병원 주문 정보 특성상 외부 유출 방지(민감정보는 아니나 거래처 단가 정보이므로 로컬 보관 원칙).
- **엑셀 호환성**: 기존에 사용 중인 두 엑셀 양식과 100% 호환되는 입출력(서식·컬럼 순서 유지).
- **응답 속도**: 사진 1장(품목 10~15개 기준) 업로드 후 인식+매칭 결과 표시까지 수 초~수십 초 이내(OCR/검색 API 응답 속도에 의존).

## 8. 사용자 흐름 (User Flow)

1. 프로그램 실행 → "새 주문 처리" 클릭
2. 병원이 보낸 주문 사진 업로드 (여러 장 가능)
3. OCR 인식 결과(품목명+수량 리스트) 확인 및 필요시 수동 수정
4. 각 항목에 대해 자동 매칭 결과 표시 → 편집 그리드에서 검수
   - 매칭 불확실 항목: 후보 선택 또는 "신규 품목 검색"(FR-4/5) 진행
5. 가격/수량 최종 확인 및 수정 (FR-2, 실시간 반영)
6. "저장" → 마스터 DB에 학습 반영 (FR-3)
7. "엑셀로 내보내기" → 발주처 양식으로 파일 생성
8. 생성된 엑셀 확인 후 발송

## 9. 화면 구성 (개요)

- **홈/대시보드**: 최근 주문 내역, 마스터 DB 품목 수, 가격 확인 필요 품목 알림
- **주문 처리 화면**: 사진 업로드 + OCR 결과 + 매칭 편집 그리드(핵심 화면)
- **품목 마스터 관리 화면**: 전체 품목 목록 조회/검색/수정, 별칭 관리, 가격 이력 조회
- **신규 품목 조사 화면**: FR-4/5 검색 결과 및 등록 처리
- **내보내기/이력 화면**: 과거 생성한 주문 엑셀 목록, 재출력

## 10. 기술 구현 방향 (제안, 확정 아님)

1인 사용, 빠른 개발/유지보수가 중요하므로 아래 조합을 우선 제안한다. (개발 착수 시 별도 기술 검토 필요)

- **애플리케이션 형태**: Python 기반 로컬 웹앱(Streamlit 등) + 데스크톱 실행 파일로 패키징, 또는 간단한 Electron 앱. 엑셀 편집 그리드 UI 구현이 핵심이므로 스프레드시트형 컴포넌트 라이브러리 활용.
- **데이터 저장**: SQLite(로컬 DB)를 기본 저장소로 쓰고, 기존 엑셀 파일 형식으로 언제든 export/import 가능하게 유지 — 지금 쓰시는 엑셀 파일을 그대로 초기 데이터로 가져올 수 있음.
- **OCR**: 한글 인식 정확도가 중요하므로 Naver Clova OCR / Upstage OCR / Google Cloud Vision 등 한국어 특화 또는 고성능 OCR API 검토. 손글씨 인식률에 대한 기대치는 보수적으로 잡고, 항상 사람이 검수하는 UI를 기본 전제로 설계.
- **매칭 로직**: 문자열 유사도(예: 자모 단위 편집거리) + 과거 학습된 별칭 사전 기반 매칭을 기본으로 하고, 애매한 경우 LLM(예: Claude API)을 이용한 의미 기반 매칭도 보조적으로 활용 가능.
- **인터넷 검색(FR-4/5)**: 검색 API(예: 웹 검색 API) 연동 + LLM으로 검색 결과 요약/정리.

## 11. 범위 밖 (Out of Scope, v1)

- 다중 사용자/권한 관리, 클라우드 동기화
- 병원 외 타 거래처로의 확장(우선 제너리스 1건에 집중, 추후 구조 확장 고려는 가능)
- 재고 관리, 회계/세금계산서 연동
- 모바일 앱 (현장 촬영은 카카오톡 등 기존 채널로 수신 후 PC에서 처리하는 것을 전제)

## 12. 리스크 및 열린 질문

| 리스크/질문 | 내용 |
|---|---|
| 손글씨 OCR 정확도 | 병원이 보내는 사진이 손글씨인지 프린트물인지에 따라 인식률 편차가 클 수 있음 — 실제 샘플 사진으로 사전 검증 필요 |
| N:M 매칭 모호성 | 같은 호칭이 여러 제조사/규격 제품에 대응하는 경우가 존재(예: 23G needle) — 과거 주문 이력 기반 "가장 자주 쓰는 매칭"을 기본값으로 제안하는 로직 필요 |
| 가격 데이터 출처 신뢰도 | 기존 자료에도 역마진/이상치 사례가 다수 발견됨 — 저장 전 이상치 자동 검증 로직이 실효성 있게 동작해야 함 |
| 인터넷 검색 결과 신뢰도 | 의료소모품/의약품 정보는 정확도가 중요 — 검색 결과를 그대로 자동 반영하지 않고 반드시 사용자 확인 단계를 거치도록 설계 |
| 급여/비급여 구분 | 기존 자료상 급여구분이 "추정치"임이 명시되어 있음 — 본 프로그램의 핵심 기능은 아니지만 참고 필드로는 유지 |

## 13. 단계별 개발 로드맵 (제안)

- **Phase 1 (MVP)**: 기존 엑셀 2종을 그대로 가져와 마스터 DB 구축. 수동으로 품목 검색·선택 + 편집 그리드 + 엑셀 내보내기 (FR-2, FR-3 우선 구현, 사진 인식은 제외)
- **Phase 2**: 사진 업로드 + OCR 텍스트 추출 + 수동 매칭 보조 (FR-1의 인식 부분)
- **Phase 3**: 자동 유사도 매칭 + 학습(별칭 자동 축적) (FR-1 고도화, FR-3 학습 강화)
- **Phase 4**: 미등록 품목 인터넷 검색 + 대안 제품 제안 (FR-4, FR-5)

### 부록: 확인이 필요한 사항

- 병원에서 보내는 사진이 실제로 손글씨인지, 프린트/캡처 화면인지 (샘플 1~2장 확보 시 OCR 사전 테스트 가능)
- 발주처가 요구하는 엑셀 양식이 거래처마다 다른지, 아니면 항상 동일 양식인지
- 마스터 DB(품목별 단가)를 현재 몇 명이 함께 갱신하는지, 향후 공동 작업 가능성이 있는지 (v1은 단독 사용 기준으로 설계됨)

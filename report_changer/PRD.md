작성자: Kevin (요청) / Claude (초안 작성)
버전: v1.1 — 저장 방식 / 오류 처리 방식 확정

## 0. 이번 버전에서 달라진 점 (v1.0 → v1.1)

1. **저장 방식 확정**: 새 파일로 저장, 저장 폴더는 마지막 사용 경로를 기본값으로 제시하되 매번 저장 대화상자를 띄워 경로를 보여주고 확인받는다.
2. **오류(미스매칭) 처리 방식 변경**: 별도의 "학습 매핑" 저장소를 두지 않는다. 대신 미스매칭 건을 사용자에게 보고 → 사용자가 확인/입력 → **기준엑셀 자체에 새 행을 추가**하는 방식으로 단순화한다. 이에 따라 "기준엑셀 vs 학습 매핑 우선순위" 질문은 자연히 해소된다 (기준정보가 기준엑셀 하나로 통일됨).
3. 괄호 제거 규칙에 대한 상세 설명을 §4.4에 보강했다.

## 1. 개요

### 1.1 배경

Kevin은 CSO(의약품 영업대행) 정산 업무에서, 거래 내역이 담긴 엑셀 파일의 "수탁업체명" 컬럼을 담당자 기준으로 매번 수기 변경하고 있습니다. 기준 데이터(기준엑셀)는 주기적으로 갱신되고, 특정 거래처(윤병옥내과의원)는 사업자번호가 아닌 제품명 기준으로 별도 처리해야 해 수작업 오류 위험이 큽니다.

### 1.2 목적

"변경할 엑셀파일"의 수탁업체명 데이터를 "기준엑셀"의 매핑 규칙에 따라 자동으로 채워주는 개인용 데스크톱 프로그램을 만들어, 정산 처리 시간과 실수를 줄인다.

### 1.3 사용 범위

- 사용자: Kevin 1인 (개인 전용 도구)
- 실행 환경: 오프라인 데스크톱(Windows), 인터넷 연결 불필요
- 형태: Python 기반 실행파일(.exe) — 설치 없이 더블클릭 실행

## 2. 확정된 데이터 스펙 (실제 파일 기준)

### 2.1 변경할 엑셀파일

- 파일 예시: `주지에스파마 정산내역_정원유니어스1일16일26일 1.xlsx`
- 대상 시트: **3번째 탭** (실제 시트명은 매번 다를 수 있음 — 예시 파일에서는 `2026년 거래처별 세부내역`)
- **헤더 행: 9행 / 데이터: 10행부터 시작**
- 데이터 끝: B열 또는 E열 값이 비어 있는 첫 행 직전까지 (예시 파일은 10~4456행, 총 4,447행)

| 열 | 헤더명(9행 값) | 용도 |
|---|---|---|
| B | 수탁업체명 | **이 프로그램이 최종적으로 덮어쓰는 값**. 처리 전에는 전 행이 동일한 값(예: "정원유니어스")으로 채워져 있음 |
| E | 사업자번호 | 기본 매칭 키 (형식: `234-90-01184`처럼 하이픈 포함) |
| F | 병원명 | 예외 케이스(윤병옥내과의원) 판별용 |
| I | 제품명 | 예외 케이스 매칭 키 + 최종 정제(괄호 제거) 대상 |

### 2.2 기준엑셀

- 파일 예시: `정산파일담당자변형_기준엑셀.xlsx`
- **탭 1: `거래처별 담당자`**
  - 1행: 제목("거래처, 사업자") — 무시
  - **2행: 헤더** (A=사업자번호, B=거래처명, C=담당자)
  - **3행부터 데이터** (예시 파일 기준 3~88행, 86건)
- **탭 2: `윤병옥내과`**
  - 1행: 제목("윤병옥내과") — 무시
  - **2행: 헤더** (A=품목, B=담당자)
  - **3행부터 데이터** (예시 파일 기준 3~136행, 134건)
- 같은 성분·용량의 제품이 표기법만 다르게(예: "글루스탑정15mg" / "글루스탑정 15mg (피오글리타존)" / "글루스탑정(피오글리타존염산염)_(16.53mg/1정)") 여러 줄로 등록되어 있고, 각 줄이 별개의 매칭 키로 취급됨 → **완전 일치(exact match) 방식**이며, 새로운 표기가 나오면 기준엑셀에 그 표기 그대로 한 줄 추가해야 매칭됨
- **본 프로그램이 향후 이 탭과 `거래처별 담당자` 탭에 새 행을 직접 추가할 수 있음** (§4.5)

## 3. 처리 로직 (실측 검증됨)

```
1) 기준엑셀 불러오기 → [거래처별 담당자], [윤병옥내과] 두 탭을 각각
   {정규화된 사업자번호 → 담당자}, {품목(원문 그대로) → 담당자} 딕셔너리로 구성

2) 변경할 엑셀파일의 3번째 탭, 10행부터 데이터가 끝나는 행까지 한 행씩:

   F열(병원명) 값에 "윤병옥내과의원" 또는 "윤병옥내과"가 포함되는가?
   ┌─ YES (예외 케이스, 실측 267건)
   │    I열(제품명) 원문을 [윤병옥내과] 탭의 "품목"과 완전 일치로 비교
   │    └─ 일치 → 그 줄의 "담당자" 값을 B열(수탁업체명)에 덮어쓰기
   │    └─ 불일치 → 미스매칭 목록에 기록 (즉시 중단하지 않고 계속 진행)
   │
   └─ NO (기본 케이스, 실측 4,180건)
        E열(사업자번호)에서 숫자만 추출해 정규화 후,
        [거래처별 담당자] 탭의 사업자번호(동일하게 정규화)와 비교
        └─ 일치 → 그 줄의 "담당자" 값을 B열(수탁업체명)에 덮어쓰기
        └─ 불일치 → 미스매칭 목록에 기록 (즉시 중단하지 않고 계속 진행)

3) 전체 행 처리가 끝나면 I열(제품명) 전체에서 괄호 구간을 제거 (§4.4)

4) 미스매칭 목록이 있으면 사용자에게 보고하고 건별로 확인/입력받음 (§4.5)
   → 확인된 값은 (a) 해당 행 B열에 반영 (b) 기준엑셀에 새 행으로 추가

5) 결과를 새 파일로 저장 (§4.6) + 처리 요약 표시
```

## 4. 기능 요구사항 (Functional Requirements)

### 4.1 파일 불러오기

- FR-1.1 "변경할 엑셀파일"을 파일 탐색기로 선택해 불러온다.
- FR-1.2 "기준엑셀"을 파일 탐색기로 선택해 불러온다 (최근 사용 경로 자동 기억, §4.7).
- FR-1.3 변경할 엑셀파일에 3번째 탭이 있는지, 기준엑셀에 `거래처별 담당자`·`윤병옥내과` 탭이 있는지 확인하고, 없으면 오류 메시지를 표시한다.
- FR-1.4 3번째 탭의 9행에서 B/E/F/I열 헤더명이 각각 "수탁업체명"/"사업자번호"/"병원명"/"제품명"과 다르면 경고를 표시한다(파일 양식이 바뀌었을 가능성 대비).

### 4.2 기본 매칭 (사업자번호 기준)

- FR-2.1 10행부터 마지막 데이터 행까지 E열(사업자번호)을 읽는다.
- FR-2.2 사업자번호는 숫자 이외 문자(하이픈 등)를 제거해 정규화한 뒤 비교한다.
- FR-2.3 기준엑셀 `거래처별 담당자` 탭에서 동일 사업자번호를 찾아 "담당자" 값을 B열에 덮어쓴다.

### 4.3 예외 매칭 (윤병옥내과 케이스)

- FR-3.1 F열 값에 "윤병옥내과의원" 또는 "윤병옥내과"가 포함되면 FR-2 대신 이 규칙을 적용한다.
- FR-3.2 I열(제품명) 원문을 `윤병옥내과` 탭의 "품목"과 완전 일치로 비교해 "담당자" 값을 B열에 덮어쓴다.
- FR-3.3 표기가 조금이라도 다르면(공백, 용량 표기 등) 매칭되지 않으므로, 신규 표기는 미스매칭 처리(§4.5)로 넘어간다.

### 4.4 제품명 정제 (괄호 제거) — 상세 규칙

- FR-4.1 모든 매칭이 끝난 후, I열 전체 데이터에서 여는 괄호 `(` 부터 그 다음에 나오는 첫 닫는 괄호 `)` 까지의 구간을 **문자열 안에 몇 개가 있든, 어느 위치에 있든 전부** 제거한다. 괄호 앞이나 뒤에 **공백을 사이에 두고** 다른 글자가 있으면 그 글자는 그대로 남긴다.
- FR-4.1a 단, 닫는 괄호 `)` 바로 뒤에 **공백 없이** 하이픈(`-`)과 텍스트가 곧바로 붙어 있는 경우(예: 제조사명이 꼬리표처럼 붙는 표기), 그 하이픈+텍스트까지 괄호와 함께 제거한다. (공백이 하나라도 있으면 별개의 단어로 보고 보존한다.)
- FR-4.2 제거 후 생기는 중복 공백은 1칸으로 정리하고, 문자열 맨 앞/뒤 공백은 제거한다.
- **동작 원리**: "괄호와 그 안의 내용물"을 오려내는 것이지, "첫 괄호부터 문자열 끝까지 잘라내는 것"이 아닙니다. 다만 괄호에 공백 없이 곧바로 붙은 하이픈 꼬리표(제조사명 등)는 괄호의 일부로 보고 함께 제거합니다.
- 실제 데이터 기준 예시:

| 원본 (I열 값) | 처리 후 | 설명 |
|---|---|---|
| `다파프로진메트서방정10/1000mg(수수료0%)` | `다파프로진메트서방정10/1000mg` | 괄호가 맨 끝 → "(수수료0%)" 구간만 제거됨 |
| `에페젠정 (AAP/카페인/에페드린)-휴온스메디텍` | `에페젠정` | `)` 바로 뒤에 공백 없이 `-휴온스메디텍`(제조사명)이 붙어 있음 → 괄호와 이 꼬리표까지 함께 제거 (사용자 확인: 회사명이므로 제거해도 무방) |
| `아나히스큐캡슐 (그린티 외 3종) (비만)` | `아나히스큐캡슐` | 괄호가 **2개** 있으면 둘 다 각각 제거됨 (첫 괄호 이후 전체를 자르는 게 아니라, 괄호 쌍마다 개별적으로 처리) |
| `엘카르닌정 (엘-카르니틴) (비만)` | `엘카르닌정` | 괄호 안에 하이픈(`엘-카르니틴`)이 있어도 그건 괄호 **내부** 내용이라 통째로 제거 대상 — FR-4.1a와는 무관 |

### 4.5 미스매칭 처리 (기준엑셀 직접 업데이트 방식)

- FR-5.1 사업자번호(기본 케이스) 또는 제품명(예외 케이스)이 기준엑셀에서 발견되지 않으면 처리를 멈추지 않고 "미스매칭 목록"에 담아 계속 진행한다.
- FR-5.2 전체 처리가 끝나면(또는 실시간으로), 미스매칭 목록을 화면에 **보고**한다: 행 번호, 매칭 실패한 값(사업자번호 또는 제품명), 병원명 등 문맥 정보를 함께 보여준다.
- FR-5.3 사용자는 건별로 올바른 "담당자" 값을 직접 입력하거나 기존 담당자 목록에서 선택해 **확인**한다.
- FR-5.4 사용자가 확인을 완료하면:
  - (a) 해당 행의 B열(수탁업체명)에 그 값을 반영하고,
  - (b) **기준엑셀 파일에 새 행을 추가**한다 — 기본 케이스는 `거래처별 담당자` 탭에 (사업자번호, 거래처명(F열 병원명 값), 담당자), 예외 케이스는 `윤병옥내과` 탭에 (품목(I열 원문), 담당자).
- FR-5.5 기준엑셀에 새 행을 추가하기 전, 원본 기준엑셀 파일의 백업 사본을 자동 생성한다(예: `정산파일담당자변형_기준엑셀_백업_20260915.xlsx`) — 실수로 잘못된 값을 추가했을 때 되돌릴 수 있도록.
- FR-5.6 이렇게 기준엑셀이 갱신되면, **같은 실행 안에서 이후 등장하는 동일 사업자번호/제품명도 즉시 자동 매칭**된다(다시 묻지 않음). 다음 번 실행 때도 당연히 자동 매칭된다.
- FR-5.7 사용자가 특정 미스매칭 건에 대해 "지금은 건너뛰기"를 선택하면, 그 행은 B열이 비워진 채로 남고 결과 요약에 "미확인 항목"으로 표시된다(기준엑셀에는 추가되지 않음).

> 참고: 이 방식으로 바뀌면서 별도의 "학습 매핑" 저장소는 필요 없어집니다. 기준정보(사업자번호/품목 ↔ 담당자)는 오직 기준엑셀 하나로 관리되며, 프로그램이 사용자 확인을 거쳐 그 파일 자체를 키워나가는 구조입니다.

### 4.6 즉석 수기 입력 기능

- FR-6.1 미스매칭 팝업을 기다리지 않고도, "매핑 목록 관리" 화면의 [추가] 버튼으로 새 행을 만들고 셀을 더블클릭해 [사업자번호 또는 제품명] ↔ [담당자] 쌍을 미리 등록할 수 있다(별도의 "매핑 직접 추가" 화면은 두지 않고 목록 관리 화면 하나로 통합).
- FR-6.2 등록 시 FR-5.4~5.5와 동일하게 기준엑셀에 새 행이 추가되고, 추가 전 백업이 생성된다(저장 버튼을 눌러야 실제 반영).
- FR-6.3 기준엑셀의 현재 매핑 목록을 조회·수정(셀 더블클릭 인라인 편집)·추가·삭제할 수 있는 화면을 제공한다(즉, 기준엑셀 내용을 프로그램 화면에서 직접 관리).

### 4.7 기준엑셀 업데이트(교체)

- FR-7.1 "기준엑셀 교체" 버튼으로 언제든 새 기준엑셀 파일을 지정할 수 있다.
- FR-7.2 마지막 사용 경로를 기억해 다음 실행 시 자동으로 다시 불러온다(경로 무효 시 재선택 요청).
- FR-7.3 기준엑셀을 완전히 새 파일로 교체하는 경우, 프로그램이 지금까지 추가해온 내용이 새 파일에는 없을 수 있으므로 이 경우엔 경고 메시지를 표시한다.

### 4.8 결과 저장

- FR-8.1 원본 "변경할 엑셀파일"은 절대 수정하지 않고, 항상 **새 파일**로 저장한다.
- FR-8.2 저장 위치는 **마지막으로 저장했던 폴더를 기본값**으로 제안한다 (최초 실행 시에는 원본 파일과 같은 폴더를 기본값으로 사용).
- FR-8.3 저장할 때마다 **파일 저장 대화상자를 항상 띄워** 경로와 파일명을 보여주고, 사용자가 확인하거나 다른 위치로 바꿀 수 있게 한다 (자동으로 조용히 저장하지 않음).
- FR-8.4 기본 파일명은 `yymmdd_원본파일명.xlsx` 형식(오늘 날짜 6자리 + 원본파일명)으로 제안한다.
- FR-8.5 처리 완료 후 요약을 보여준다: 전체 행 수, 기본 매칭 건수, 예외 매칭 건수, 이번에 새로 확인해 기준엑셀에 추가된 건수, 건너뛴(미확인) 건수.

## 6. 화면 구성 (초안)

1. **메인 화면**: 변경할 엑셀파일 선택(끌어놓기 지원) / 기준엑셀 선택·교체(끌어놓기 지원, 마지막 경로 자동 표시) / 기준엑셀 매핑 목록 관리(추가·인라인 수정·삭제) / 변환 실행 버튼 / **변환 결과 영역**(메인 화면에 내장 — 변환 전에는 비어있다가, 변환 후 요약 통계와 미스매칭 처리 내역 표, [결과 파일 열기]/[폴더 열기] 버튼이 그 자리에 채워짐. 별도 팝업이 아님)
2. **미스매칭 확인 화면**: 미매칭 건 목록(행 번호·매칭 실패 값·병원명), 각 건마다 담당자 입력창(직접 입력 또는 목록 선택) + [기준엑셀에 추가] / [건너뛰기] 버튼
3. **저장 대화상자**: 마지막 저장 폴더를 기본값으로 표시, 파일명 제안(`yymmdd_원본파일명.xlsx`), 사용자가 경로/이름 확인 또는 변경 후 저장

## 7. 남은 확인 사항

현재까지 확인된 내용으로 개발 착수가 가능한 상태입니다. 다만 실제 사용 중 아래와 같은 세부 케이스가 나올 수 있어, 개발 진행 중 필요하면 추가로 여쭤볼 수 있습니다.

- 기준엑셀에 새로 추가하는 "거래처명"은 F열(병원명) 값을 그대로 쓰면 되는지, 아니면 별도로 입력받아야 하는지
- 미스매칭 확인 화면에서 여러 건을 한 번에 처리(예: 같은 담당자로 일괄 지정)할 필요가 있는지
